# 先搞清楚：这套系统是什么、赛题要求什么、屏幕怎么开

更新：2026-10-25。依据硬盘赛题原文、工程代码、历史审计和本次实机检查。

## 用一句话理解作品

队友选择的作品方向是“智能无线电频谱感知与调制识别系统”，可以理解为一台带AI的无线电信号分析仪。

它接收一段无线电信号，分析这段信号的变化规律，再判断它采用了BPSK、QPSK、QAM、FM等哪一种调制方式。调制方式就是“把信息装到无线电波上的方式”。类别、频谱、星座图和处理时间是计划展示给评委的信息。

工程早期名称是“智频感知：FPGA-NPU异构宽带射频智能认知系统”。早期8类、后来24类、旧屏幕23类是不同阶段的版本，不能混在一起使用。

## 复旦微赛题真正要求什么

赛题原文：E:\嵌赛\de2aca5a-535d-4288-aecd-aed3d0cf5841.pdf，标题《全国大学生嵌入式芯片与系统设计竞赛2026 FPGA创新设计赛道选题指南》。主要要求在第5—7页。

这是开放选题：射频识别是参考方向之一，24类、8类、Pluto、AD-AMR论文都不是赛题指定要求。

必须围绕一个具体应用场景，完成：

1. 至少一种AI算法部署到30TAI，包含转换、量化/精度分析、仿真、上板推理、性能测试。
2. 至少一项FPGA开发，例如接口、预处理、后处理、硬算子或实时控制。
3. 说明CPU、NPU、FPGA分别做什么，并形成输入→处理→推理→输出/交互/显示的闭环。
4. 提交可复现工程、说明、测试数据和视频/实物演示；性能数据必须可信。
5. 记录用了哪些AI工具、用在什么环节、工作量占比、人工审核和修错情况。

所以，交作品的重点是“明确场景、完整闭环、真实指标、可复现”，不应为了凑24类而牺牲整个系统的稳定性。也不能只展示电脑上训练的准确率。

## 手上这些设备分别干什么

| 设备/模块 | 作用 | 当前状态 |
|---|---|---|
| 电脑+TX Pluto | 产生已知调制信号，充当测试信号源 | 本次已经实际使用 |
| RX Pluto | 射频接收并采样成I/Q数字数据 | 数据USB现接悟净板 |
| 悟净CPU | Linux、USB采集、同步、频偏补偿、17抽头均衡、调度 | 本次95%原型在这里运行这些处理 |
| 悟净NPU | 运行AD-AMR 24类BF16神经网络，输出24个分数 | 本次真实板端已经验证 |
| 悟净FPGA/PL | 现有组合位流包含NPU连接/数据通路、HDMI帧缓冲与输出；另有物理特征RTL工程 | HDMI硬件身份和帧缓冲初始化已实测通过；不能把本次CPU均衡称为FPGA加速 |
| HDMI屏幕 | 展示状态、类别等信息 | 原界面已启动；实际屏幕连接/画面尚待用户确认 |
| JTAG下载器 | 调试、加载FPGA位流 | 不是日常识别时的数据线 |

注意：FPGA工程里有Power/Lag等物理特征模块，不等于它已经接进当前AD-AMR识别主链。若答辩主打“FPGA信号预处理加速”，需要补最终运行链证据和CPU/FPGA性能对比。

## 现在实际跑通了哪一条链

电脑发射Pluto → 同轴射频线 → 悟净板接收Pluto → 板端CPU恢复IQ → 板端NPU识别。

本次结果：24类×每类10个不同源波形，正确228/240=95.0%，失败0；每波形8窗口logits平均，NPU共推理1920次，apply=1、reset=1919、discipline=1。板端耗时中位数约184毫秒。

这只是高SNR、带公共前导、有线回放链的结果。源波形来自原RadioML资产，多数属于原预训练数据划分的训练部分，所以它验证的是链路恢复，不是未见数据泛化。还没证明任意外部未知信号、无前导、空口、多径或低SNR场景的同等准确率。

## HDMI屏幕怎么接、怎么开

1. HDMI线：悟净板的HDMI输出口 → 显示器/小屏的HDMI输入口。不要接到电脑的HDMI输出口。
2. 给屏幕供电，打开屏幕，选择HDMI输入。若是独立小屏，HDMI线通常不负责给它供电，按屏幕电源接口要求供电。
3. 如果要触摸操作，还需要屏幕触摸USB接到悟净板USB Host；HDMI线只传画面。当前日志为UI_TOUCH status=DISCONNECTED，不影响单纯显示。
4. 已在板端启动原有界面。实际日志：

   UI_VERSION_CHECK ... version=0x20230218 ... ok=YES
   UI_FB_READY phys=0x30100000 frames=2 frame_bytes=1843200 refresh_hz=30

   这证明显示程序与帧缓冲初始化成功，不等于已目视确认屏幕亮起。

需要手动重新开启时，在悟净板串口终端输入：

```bash
cd /root/realrf_finetune_pilot1_test_1773373090
bash scripts/start_live_rml23.sh
```

查看启动日志：

```bash
tail -n 25 /tmp/sdr_ui_live_rml23/ui_live_rml23.log
```

如果显示已经运行，不要反复启动第二个界面进程。当前界面没有识别生产者送数据，看到WAIT/STALE/等待数据属于正常状态，不是模型识别坏了。启动界面本身不会开始Pluto发射或识别。

Lite手册的HDMI输出说明在第25页；旧界面固定1280×720。部分小屏的原生分辨率不同，须在实物上确认能否接受720p输入。

当前尚未修改开机自启或启动介质。历史记录显示合并位流曾依赖JTAG临时加载，重启后可能丢失HDMI功能；遇到重启黑屏，不能只反复起UI或随意烧写Flash，应重新检查硬件版本门和启动位流。
