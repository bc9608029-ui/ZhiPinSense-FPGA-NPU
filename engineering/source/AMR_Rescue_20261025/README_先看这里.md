## 改了什么

- 固定、所有类别共用的QPSK公共前导与不同的尾参考，避免首尾同步歧义。
- 根据公共前导估计频偏，补偿后按相应旋转基函数建模直流，避免把直流当成常数硬减。
- 使用17抽头复数FIR估计并均衡通道，处理分数定时及频响失真；头尾参考估计缓慢幅相变化。
- 用公共参考重建误差检查有效性；不读取类别、原始待识别IQ或逐类参数来做接收恢复。
- 保留原有NPU模型和每帧reset纪律，通过Unix socket送 `[2,1024]` FP32输入。
- PC→板端TCP只传序号和采集控制，不传样本IQ或类别答案；私有真值在电脑，采集结束后离线评分。

`pilot_recovery.py` 是板端实际恢复算法；`pluto_link_probe.py` 是libiio 0.26接口；`pc_live_tx.py`/`board_live_rx.py` 是真实收发端；`npu_stream.cpp` 复用原工程的 `NpuClassifier24`。不需要pip安装新包，板上复用了已有torch环境中的NumPy/SciPy。

## 限制和剩余工作

1. 这是**受控发射、公共前导、有线连接**的原型。没有公共前导的陌生信号、真实空口、多径、低SNR、不同码率和采样率都尚未验收。如果赛题要求任意外部信号盲识别，需要另一条同步和训练路线，不能把本结果直接替代。
2. 波形来自原RadioML筛选资产，多数源样本属于原预训练数据划分中的训练部分；当前是链路修复验证，不是未见样本泛化测试。原项目S3/S4资产未用于本次调参或评分，后续固定方案后再做独立验证/一次最终测试。
3. 新原型尚未接入旧HDMI界面、频谱扫描、旧生产协议或开机自启。启动入口是上面的两个命令；不要把它称为原完整作品已验收。
4. 一轮每类只有10个独立波形；重复8个窗口不等于多了8个独立测试样本。95%只适用于这次240个样本和硬件条件，不能承诺后续每次都95%。
5. 目前代码在板端独立目录，运行日志和采集文件在/tmp；重启前需要保留重要结果。保存的PC评分JSON已随本包提供。
