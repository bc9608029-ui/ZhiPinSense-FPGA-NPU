# 多频点发射准备与验证任务书

## 目标

为“定频、搜索锁定、连续巡扫＋最近10条历史记录”提供可信的单路/双路发射测试源。只完成发射源准备和验证，不修改接收模式，不部署失败的 AC，不训练、不改模型/公共帧/two-DC/FPGA 位流。

电脑工作自主完成，不反复询问 yes/no；本任务不自动开始射频发射。离线交付后由用户安排接线与设备测试。正式240＋240回归不在本任务范围。

## 一、先读与输入

- F:\rml24_ac_execution_20261029\NEXT_AGENT_HANDOFF.md
- F:\rml24_ac_execution_20261029\two_target_tx.py
- F:\嵌赛\HANDOFF_AC_NEXT_TEST_20261029.md
- 既有冻结公共帧生成器、源 manifest 和数据集，从上述 TX 脚本真实 import/路径追溯。

历史双路：TX LO 2401.8MHz、Fs10.24MS/s；将Fs2.56MS/s公共帧4倍重采样后移频±1.8MHz，形成2400和2403.6MHz。它确实发射过，但尚未独立证实频谱/重采样正确。接收端曾报告±2.56MHz别名；不可仅凭这一现象判定发射错误或接收错误。

全部路径以实际 F 盘存在内容为准，旧脚本硬编码 E 盘必须参数化。原文件和失败记录保留，不就地改历史。

## 二、实施顺序

### 1. 来源与合同冻结

新建独立工作目录。记录源文件 SHA、生成器及全部传递依赖 SHA、类别映射、消息种子、原始帧布局/长度、载荷重复方式、源采样率、公开幅度规则和 Radio.send 的实际 int16 缩放/交织/截断规则。

保留单路冻结输入逐字节不变。双路仅在外层进行统一重采样、移频、求和与公开增益处理，不按类别调参，不用 RX 标签反馈调波形。

### 2. 先做可审计的纯数字验证

生成并冻结：A单路、B单路、A+B双路、全零静默四种波形；A/B单路也走与双路完全相同的高采样率、LO和移频路径，不能切换成不同发送配置冒充可比对照。

验证频率轴、移频符号、两路实际占用带宽、guard及Nyquist余量；根据真实频谱确认间隔足够，不预先承诺“任意信号间隔都能分开”。周期发送首尾边界也要检查，记录额外不连续和可能杂散。

离线分别下变频、滤波、抽取每一路，补偿确定的滤波延迟/边界；用已知生成信号作测试真值，输出相关度、NMSE、公共帧可恢复性及载荷/张量对照。该 oracle 仅用于离线验证，不能接入生产 RX。

区分浮点波形与最终设备 int16 波形：对最终量化数据检查 I/Q 峰值、饱和比例、每路 RMS、总 RMS、PAPR；不得仅检查 send 前的浮点幅度就宣称硬件不削顶。用同一固定每路幅度保持A-only/B-only/both可比，双路叠加预留余量。

量化前后输出 PSD 图和机器可读频谱指标。冻结带内/带外区域及泄漏、镜像、量化误差等验收阈值，说明依据，禁止看到结果后随意放宽。

### 3. 发射程序工程化

明确参数：--tx-uri、--manifest、--dataset、--out、--dry-run、--transmit，以及场景和时长。默认 dry-run，不扫描后自动选择任意设备发射；实发前验证明确 URI/序列号。

配置 TX LO/Fs/BW/增益并读回，不符即停止；RX不接收真值、频率列表或发射开始通知。TX私有日志可包含真值，供事后离线计分。

每个相位写真实事件：prepared/start_requested/active/stop/restore，注明 wall-clock 与 monotonic 时间、发送波形 SHA、URI/序列号、配置读回。禁止把离线报告的 rf_started=false 当作运行状态；配置读回不等于独立证明RF已经辐射。

支持 Ctrl+C/停止文件、有界时长、异常清理；先销毁发送缓冲，再恢复原属性并读回。逐项记录恢复成功/失败，不以退出码0掩盖恢复错误。没有独立停发/恢复证据不能写“停止已验证”。

### 4. 完整离线测试

至少覆盖：源SHA错误、路径缺失、错误URI、配置读回不符、移频符号/频率轴、双路峰值超限、最终量化饱和、重采样恢复、异常退出清理、停止及恢复失败。模拟设备与真实设备证据分开。

提供可复现命令和依赖版本。无 SDR 时不得把模拟通过写成RF通过。

## 三、后续设备短测方案（交付方案，暂不自动发射）

1. 确认当前稳定接收服务、原位流和连接方式。若进行原始IQ诊断，独占RX并保存原服务状态，结束恢复，禁止并发争抢SDR。
2. 同一TX配置依次静默、A-only、B-only、both、撤去B、静默；推荐短相位，具体时长按RX完整扫描耗时冻结，保证每相位足够观察，不将跨相位残留误判为伪目标。
3. 用稳定定频接收分别在A/B真实中心验证公共帧与分类；同时原始IQ频谱取证。固定接收配置、避免削顶，报告实际读回。
4. 检查两路中心、真实占用带宽、杂散/镜像；必要时在疑似别名频点采集。关联原始IQ频谱与相关检测，区分“真实RF能量”和“相关器虚假频率估计”。仅有相关器输出不能证明真实额外发射信号。
5. 没有频谱仪时如实写“第二台SDR测量”，不能称计量校准；SDR本身的混叠/前端影响仍需通过不同LO或采样率等受控对照排查。生产参数不因诊断改变。
6. 逐路通过再验收双路。如果两路单独可识别、双路失败，先区分TX叠加、接收带宽/动态范围和接收算法，不直接归咎模型。

原搜索锁定接收器不能汇总多目标，因此不可用它“只显示一个目标”判TX失败。巡扫功能尚未实施，TX短测验证与巡扫整体验收分开。

## 四、必须交付

- HANDOFF_MULTIFREQUENCY_TX.md：唯一入口，准确状态、路径、SHA、命令、设备短测与恢复顺序。
- CONTRACT.json：源身份、频点/采样率/幅度/阶段计划、冻结验收阈值。
- 参数化TX程序及只读dry-run入口；保持历史原件。
- 四场景量化数据或可确定性重生成清单、逐文件SHA。
- 纯数字分路恢复报告、PSD图、量化/泄漏指标、测试日志。
- 板端短测手册及结果表模板，注明待执行项。
- 单一压缩包、内部逐文件校验及包外整体SHA，独立解包验证。

## 五、完成判据

离线准备完成＝来源闭包清楚、四场景可复现、最终量化检查通过、纯数字两路恢复通过、程序控制/清理反例通过、包独立核验通过。最高写 OFFLINE_TX_PREP_VERIFIED_RF_PENDING。

可信双频点RF源＝后续真实单路/双路对照及频谱/接收证据通过，真实停发恢复验证通过。没有这些证据不得写 RF_TX_VALIDATED，更不得据此宣称巡扫或模型验收通过。
