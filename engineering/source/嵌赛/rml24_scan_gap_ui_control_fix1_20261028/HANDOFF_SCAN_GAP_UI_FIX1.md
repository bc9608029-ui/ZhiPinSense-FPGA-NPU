# RML24 扫频缺项 + 频率触控 UI Fix1 交接

状态：`READY_FOR_BOARD_BUILD_AND_RF_RETEST`。这是电脑侧候选，不是 RF PASS，也没有替换正式自启动。

## 1. 本轮解决什么

1. 保留已冻结的“八段重复载荷相干平均”候选与 two-DC，不改模型、公共帧、检测门限或 240 固定分母。
2. 修复扫频短暂漏检触发约 20 秒全频段重扫的问题。
3. 第五页只保留两个用户模式：`FIXED` 与 `BAND SCAN`。
4. 增加四个可触控输入：定频频率、扫频起点、终点和步进（单位 MHz）。
5. `AUTO LOCK` 不再作为第三个用户模式；锁定、重捕获和重扫是 `BAND SCAN` 内部状态。

## 2. 为什么这是有证据的修改

原验证 `candidate_scan01` 为 230/240、缺 4 项。缺项 source index 为 65、66、121、122。原始事件时间轴中恰有两段 20.881 s / 20.880 s 的停顿，均紧跟 `NO_VALID_PUBLIC_FRAME`，每段覆盖后续两个 6 秒发射槽。详见 `results/gap_root_cause.json`。

原接收器连续 3 次漏检即丢锁并做 11 点全扫。本候选改成同时满足：

- 连续漏检至少 5 次；
- 连续漏检持续至少 1.0 秒；

才允许全扫。任一命中立即清零。该策略只读公共帧检测结果和单调时间，不读标签、载荷、logits 或预期频点。

这能针对缺项根因，但在 RF 重测前不能宣称缺项已经归零，也不能宣称剩余分类误差已修复。

## 3. AutoLock 的最终处理

- 用户层：删除，避免与扫频概念重复和误导。
- 后端协议：只接受 `SET_MODE FIXED` / `SET_MODE BAND_SCAN`；`AUTO_LOCK` fail-closed 拒绝。
- 扫频内部：保留 `SCANNING / LOCKED / REACQUIRING` 状态显示。自动锁定仍然存在，但它是扫频算法行为，不是第三种工作模式。
- 兼容性：未改历史冻结的通用枚举文件；新触控映射不会发出 AutoLock 命令。
