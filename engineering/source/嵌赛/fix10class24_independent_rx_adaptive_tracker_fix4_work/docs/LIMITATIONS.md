# Fix4 局限性（LIMITATIONS）

任务：`M29-RML24-FIX10CLASS24-INDEPENDENT-RX-ADAPTIVE-TRACKER-FIX4`
状态：`…-FIX4-LIMITATIONS-COMPLETE`（纯离线，不碰板/不训练/不发射）

本文记录 Fix4 的**结构性边界**与**经验负结论**，用于支撑 §9 失败归因
（failure triage）。所有结论只来自两条真实双 SDR 捕获 + 冻结 fix2 恢复链 +
冻结 BF16 模型，不使用任何未知载荷 IQ / 标签 / logits 调参。

---

## 1. 公共参考的可观测性边界（§9-1 成立）

Fix4 的 DC/LO 泄漏跟踪器**只允许**读 4 个公共参考块的块均值
（settle 1536 / train 2560 / guard 57856 / tail 59392）。Phase 1
可观测性审计（`observability_fix4.py`）测得：

| 量 | rf_fix2_target | old_rf_session |
|---|---|---|
| drift_span 中位数 | 12.0 | 13.6 |
| 块间散点（scatter）中位数 | 6.1 | 5.8 |
| real 分量非单调帧数 | 22/24 | 24/24 |
| imag 分量非单调帧数 | 17/24 | 24/24 |

结论：

- **散点 ~6 与锚点幅度 ~7 同量级**：4 个锚点本身信噪比不足以分辨
  漂移的确定性部分与块内噪声。
- **real 分量在 22/24（target）/ 24/24（old）帧非单调**：任何「单调 /
  线性 / 低阶多项式」内插都必然在载荷区间（3072:56832，占 90% 帧长）
  产生与真实漂移同量级的误差。
- 这正是 T1（分块线性）与 T3（三次 Hermite）把门拒率打成 **0/24** 的
  直接原因：内插器过拟合了 4 个散点，把错误的 DC 形状注入载荷区间，
  `training_residual_rel` 反而高于 0.100 门。

**归因（§9-1）**：载荷内部的漂移（3072:56832 区间）**对 4 个公共参考块
不可观测**。这是信息论层面的边界，不是跟踪器结构不足。

## 3. 失败归因（§9，逐条裁决）

1. **（§9-1）公共参考对载荷内部漂移不可观测 —— 成立（主要）**：
   Phase 1 非单调性 22–24/24 + scatter≈锚点幅度，结构性封顶任何
   4 锚点内插器。
2. **（§9-2）LO/DC 不是唯一/主要失配原因 —— 部分成立**：即便把 DC 减到
   门内（C1 门过 24/24、residual≤0.100），端到端仍只有 2/24，说明 DC
   之外仍有导致误分类的 RF 域偏移（见 fix3-R1 与 ac-input-audit 的
   「64/128QAM→256QAM 同族升阶」）。
3. **（§9-3）模型输入仍存在其他 RF 域偏移 —— 成立**：门内 24/24 帧中
   仅 2 帧分类正确，与 fix3 `STATIC_DC_MARGINAL_NO_RECOVERY` 一致；
   剩余偏移不在 DC/LO 主轴上（幅度合同、IQ 不平衡、非线性、时变）。
4. **（§9-4）恢复器结构不足 —— 不成立（本任务未证实）**：广线性
   `y=ax+b·conj(x)` + (cfo,τ) 联合网格在 fix2 已把数字回放做到 23/24；
   本任务未发现「换一种恢复器结构」即可突破的证据。
5. **（§9-5）冻结模型需要 RF 域适配 —— 支持**：上述 (2)(3) 表明，在
   不训练、不改 0.100 门、只用公共参考的红线内，剩余偏移无法靠 DC
   跟踪消除；这指向「模型需要 RF 域适配/重训」，而非「DC 跟踪器再改进」。

**总判决**：Fix4 在红线内（不训练/不改门/只用公共参考/不读载荷）无法
把两条会话的端到端从 2/24 提升。判决等级由 `judge_fix4.py` 输出
（预期 `NO_IMPROVEMENT` 或 `MARGINAL_ONLY`，见 `results/fix4_verdict.json`）。
