# Fix4 REVIEW-R1 局限与边界 — 修正残差定义后的诚实边界

任务：`M29-RML24-FIX10CLASS24-INDEPENDENT-RX-ADAPTIVE-TRACKER-FIX4-REVIEW-R1`
状态：`…-REVIEW-R1-LIMITATIONS-COMPLETE`（纯离线）

本文件只陈述边界，不夸大、不把离线改动称为 RF_PASS 或项目完成。

## 1. 「MARGINAL_ONLY」的实质：一帧噪声边缘，非恢复

- 唯一的「进步」是 rf_fix2_target 会话 T6 = 3/24，比基线 2/24 多 1 帧。
- 该 1 帧**未在 old_rf_session 会话复现**（该会话 T6 仍 2/24）。
- 阶梯机械地把 `hi = max(3,2) = 3` 判进 3–5 的 MARGINAL_ONLY 档，但这**不应读作
  「有边际恢复」**——单帧、单会话、未被复现，属噪声级涨落。

因此本判决与 fix3-R1 的 `STATIC_DC_MARGINAL_NO_RECOVERY` 实质一致：修正残差定义后，
**仍然没有可恢复的载荷内 LO 轨迹**。

## 2. 命中的 3 类不构成稳定恢复

T6（rf_fix2_target）命中 3 类 = 256QAM、AM-SSB-WC、AM-SSB-SC：

- **仅恢复一个先前错误类别**：sid17 256QAM 在 C1 下被误判 8ASK，T6 纠正为 256QAM；
  但只发生在 rf_fix2_target 一轮，old_rf_session 中 T6 对 sid17 仍误判 8ASK，
  **未复现**，不构成稳定恢复。
- AM-SSB-WC / AM-SSB-SC 是 fix3-R1 已确认的「WC/SC 判别稳定对」（易分类对）。
- 没有任何真正的失败类（64QAM/128QAM/QPSK/8PSK/16PSK/…）获得可复现恢复。

## 3. 需求 10 的固定措辞（数学事实，非物理断言）

> 在没有载荷内部导频的情况下，任意无约束的载荷内轨迹不能由首尾参考唯一恢复。

20 个残差锚点只覆盖首尾公共块（settle 4 + train 4 + guard 8 + tail 4）；载荷区间
（3072:56832）无任何导频，任何内插器只能「过首尾锚点外推」，结构性欠定。实测的
nonmono(im)=24/24、scatter/|anchor|≈0.6 只是这一不可观测性在数据上的体现。

**本报告不**把这一数学事实等同于「真实 LO 一定在载荷内非单调变化」——后者需载荷内
导频才能验证，现有公共参考无法证明，也无法证伪。

## 4. 修正定义修的是什么、没修的是什么

- **修了**：残差定义正确性——不再把 train/tail 已知序列自身的非零均值（390.4 / 64.0）
  混入 DC。数字域残差锚点从「泄漏 ~390」回归到 0.000。
- **没修**：载荷内 LO 轨迹的**可观测性**。公共参考残差只能提供 20 个首尾锚点，
  载荷内轨迹仍欠定，任何 tracker 都只能外推。

## 5. 边界与红线

- 纯离线；不碰板、不操作 SDR、不发射、不训练、不改模型/公共协议/门限（0.100）。
- 24 分母不剔除；门拒样本不算进分子。
- 不写 RF_PASS / PROJECT_COMPLETE；不称「项目完成」。
- `board_patch_allowed = false`（两会话 best 均远低于 12/24），**不生成 BOARDTEST**。

## 6. 后续可能的证据缺口（仅供记录，非本任务范围）

- 载荷内 LO 轨迹唯一可恢复的充分条件是**载荷内导频**，而公共协议固定、不新增。
- 在现有协议下，「载荷内轨迹不可唯一恢复」是结构性的，不是 tracker 算法问题。
- 若需在保持公共协议不变的前提下验证「真实 LO 是否在载荷内非单调变化」，需要载荷内
  导频或独立 LO 监测，二者均不在当前协议/红线内。
