===== PAGE 2 =====
1 开发环境准备 
1.1 注意事项 
1. 30TAI 器件的数据库和其它PSOC 器件的数据库互斥，建议用户安装2 个
vivado 来开发AI 器件和非AI 器件（可以修改vivado 图标的名称易于区
分）。 
2. 在替换完此数据库之后，进口以及我司PSOC 器件会受到替换数据库的影响
在使用时可能，请在要使用其它器件时首先执行reset_database_to_default
命令以保障其它器件的正常使用 
3.  如果使用新增器件流程添加过FMBH45、FMQL15 的器件，需使用
fmsh_uninstall_device（fmql15/fmk230t/fmk300t）、
remove_fmk50rh_fmbh45_database(fmk50rh/fmbh45)来恢复数据库,以避
免和JFMQL30TAI 器件的数据库冲突 
4.  查看是否正确替换过数据库文件 
 
新增器件工程可以使用在打完patch 之后执行database_check 命令查看数据
库是否被替换，如下图1-1 所示，此命令执行需要数分钟。 
 
图1-1 检测jfmql30tai 数据库是否被替换 
5.  位流时不要指定路径，补丁会调用PROCISE 自动打位流补丁。

1.2 工具及环境准备 
1.VIVADO：VIVADO2018.3 版本 
2.IP 补丁工具：5.3.1.8 以及以后版本; 
  注：IP_PATCH 工具使用参考《IP_PATCH 工具使用说明_V5.3.1.8》 
3.替换VIVADO2018.3 数据库，替换为复微器件 
 
使用VIVADO 2018.3 打开任意工程，然后参考《IP_PATCH 工具使用说明
_V5.3.1.8》第二章、第三章、第四章，依次执行工具包解压，设置环境变量，加
载工具包三个步骤，加载完工具包后执行命令replace_7z030ai_file 替换器件数据
库，如图1-2 所示 
 
图1-2 替换器件数据库 
在使用IP_PATCH 之后的VIVADO 的TCL console 中可以使用
reset_database_to_default 命令来恢复替换的数据库。如图1-3 所示是执行命令成
功后的打印信息。 
 
图1-3 恢复替换数据库 
注：  
此替换数据库的操作对一台电脑只需执行一次就会一直生效，无需重复操作。 
reset_database_to_default 指令会恢复所有替换的数据库

设置PROCISE，如图1-4
