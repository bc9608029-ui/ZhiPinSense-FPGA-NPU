# RML24 电脑发射控制台

启动：Windows PowerShell执行 `& 'D:\Anaconda\python.exe' 'F:\嵌赛\rml24_tx_console_20261029\app.py'`。

首次打开不会访问SDR或发射。默认离线演练；点击校验与预览会校验真实IQ的SHA、使用冻结build_frame构造公共帧，并显示第一个实际载荷的数字频谱。频谱是归一化dB，不是RF实测，不是发射输出功率。

## 已实现

- 中文高DPI桌面UI：调制、MHz频率、TX硬件增益、USB URI、保持时间、会话时限、数据路径和解释器。
- 单类重复、24类轮播。每类从现有冻结清单选择第一个样本，重复发送同一公共帧；不生成新波形、不重训。
- 显式真实TX开关，默认关闭。点击开始前重新校验资产；模式/参数运行中锁定。
- 独立进程发射，不与RX建立任何连接，不传类别、样本IQ、逐样本恢复参数或开始通知给RX。所有类别真值只存在PC端。
- 停止按钮/Esc/关闭窗口通过stop.request请求工作进程停止循环、销毁cyclic buffer并恢复属性；每次等待以50ms分段，底层IIO调用仍可能阻塞到驱动超时。
- 属性写入后回读；异常执行finally清理。恢复结果来自旧Radio.close返回值，只证明恢复写入未报告错误，不是恢复后的独立读回验证。
- 计划/config、带时间戳的事件、result落在runs/会话目录。演练与真实TX明确区分，UI不把检测到URI称为已连接。

## 使用

1. 校验与预览，确认资产路径存在。包内assets含Stage7纯净生成波形集的24类各一个既有样本及SHA清单，原字节复制，不重新生成。默认直接使用这24个样本；高级路径可切回外部完整清单。
2. 可选检测USB（只读），或填写TX的URI。界面程序与工作进程可以用不同解释器；运行解释器默认D:/radioconda/python.exe，需numpy/scipy和libiio.dll。
3. 先离线演练，检查开始/停止与日志。24类一轮至少24×(保持+间隔)，默认6s保持和0.25s间隔即150s；60s会话会提前结束，UI会提示。
4. 实际同轴链路就绪后由用户启用真实TX并点击开始。默认2.4GHz/2.56MS/s/18MHz/-40dB沿用已测配置；改变频率/增益不自动继承历史准确率。
5. 点击停止，等待结束状态。若恢复异常或进程崩溃，界面明确显示状态未确认，需要人工核查SDR。不要用任务管理器杀死工作进程作为常规停止方法。

多信号同时发射按钮暂禁用：对应正式链路尚待验收，不以24类轮播冒充同时多信号。

仅本轮离线验证通过后可称电脑界面就绪；本轮未连接SDR、未调用扫描、未发射，真实设备兼容和停止恢复仍待用户硬件验收。
