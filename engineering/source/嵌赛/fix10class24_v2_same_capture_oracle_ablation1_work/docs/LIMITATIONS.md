# M29-RML24-V2-SAME-CAPTURE-ORACLE-ABLATION1 — 局限

状态：`…-LIMITATIONS-COMPLETE`（2026-10-21 复审修正后）

## 1. 本消融能确定什么

- 生产恢复可逐字节复现（48/48）；生产 e2e（门控）与强制 O0 分列（fix2 1/24 vs 2/24）。
- 窗(O1)/尺度(O2)不是瓶颈；直流(O3)是最大可修正单因子（fix2 +3 帧）；交叉验证仿射
  上界(O5) fix2=5/24、old=2/24，远低于数字基线 23/24。
- 固定仿射修正（窗+尺度+直流+广线性）不足以把真实 RF 载荷修到数字基线（H4 支持）。

## 2. 本消融不能确定什么

- **不能**区分「非仿射」（每时刻都不可仿射描述）与「时变」（各时刻仿射但映射随时间漂移）。
  二者都使 O5 交叉验证残差高，需另立 RF 域诊断（LO 相位噪声/漂移、非线性、时变 IQ
  不平衡）才能定量拆分。
- **不能**确定具体物理环节（LO 泄漏 / 放大器非线性 / 相位噪声 / 时变增益的相对占比）。
- **不能**据此声称「修接收链可达多少精度」——本消融只证明「固定仿射修复的上界」，不证明
  存在任何无训练修复方案。
- **不能**排除模型 RF 域失配（H5 未决）：数字基线 23/24 只证数字 v2 域健康，不覆盖真实
  RF 残余失真；即便失真可修，冻结模型对真实 RF 域是否仍有效未证明。
- **不能**把 O5 仿射上界当作可部署方案：O5 用原始载荷 x 作 oracle 拟合，违反「原始载荷
  不得进入接收算法」红线，仅限离线诊断。

## 3. 口径与单位局限（复审修正）

- O0 分两个口径：生产 e2e（板端门控 `board_pred`）与强制 O0（主机 BF16 强制分类）。二者
  数字不同（fix2 1/24 vs 2/24），已分列，不得互代。
- O2 是「payload-oracle 复标量」（对原始载荷 LS 拟合），**不是** manifest 发送尺度；manifest
  尺度已在生产 ×1/S_v2 施加，「纯 manifest 尺度」oracle 与 O0 退化等价。
- 载荷窗残差统一为 NMSE=|z-x|²/|x|²、NRMSE=sqrt(NMSE)（参考归一化）。生产门
  `training_residual_rel ≤0.100` 是**训练段、接收能量归一化** sqrt(|e|²/|r_train|²)，
  与载荷 NRMSE **不可直接比较**；本消融仅把 NRMSE 用于 oracle 级间相对比较，不写
  「~6× 门」之类跨口径断言。

## 4. 数据固有局限

- 每类仅 1 个源波形（1 实现/类），无类内方差估计。
- 真实 RF 仅 2 会话（且使用不同恢复链：fix2 vs old），样本量远低于任何结论性 RF 建模门槛。
- 两会话的仿射上界不同（5/24 vs 2/24），说明失真强度会话相关；2 会话不足以量化会话分布。
