## 本轮已补齐的电脑侧准备

1. 新增 `FIXED`/`BAND_SCAN` 双模式接收入口，定频默认参数及 two-DC/NPU 路径不变。
2. 新增只依赖公共重复训练段的宽频偏粗捕获。它在每个 LO 点寻找公共帧，不使用类别、真值或载荷。
3. 扫描首次找到信号后锁定 LO；后续每帧只做一次锁定检查。检查失败才重新扫，避免每帧遍历全频段。
4. 新增 RX LO 写入、读回、容差检查、缓存刷新和恢复适配层；未知板端接口会 fail-closed。
5. PC 发射程序新增公开 `--center-hz`，默认 2.4 GHz 时生成的发射帧与 Stage 7 逐字节一致。
6. UI 增为四页：分类、频谱/瀑布、星座、模式。MODE 页恢复触控；AUTO LOCK 明确不支持并由接收器拒绝。
7. UI 控制通道实现 `STATUS` 及 `accepted/applied` 两阶段应答，Linux AF_UNIX 实测通过。
8. 修改后的完整 UI 在 WSL `g++ -Werror` 编译通过。
9. Stage 7 真实 RF 原始捕获被用于无标签前端回放；这是开发回放，不等于独立扫频 RF 通过。

## 仍必须用设备完成

1. 板端确认遗留 `Radio` 包装器能读写 RX LO，并核对 readback。
2. 板端原生构建四页 UI，实屏验证 MODE 页触控与控制 socket。
3. 先跑定频回归，确认新增文件没有降低原 98.96% 基线。
4. 用偏离 2.4 GHz 的 TX 中心频率跑窄扫频，再扩展扫频范围。
5. 分别记录首次扫描时间、锁定后单帧时间、误检、漏检、24 类准确率和恢复情况。
6. 最终再决定是否把双模式服务接入已验证的开机自启动；本包不会自动改 systemd。

因此，本轮能诚实写的是“电脑侧准备完成，可进入板端构建和 RF 验证”，不能写“扫频完成”或“RF PASS”。
