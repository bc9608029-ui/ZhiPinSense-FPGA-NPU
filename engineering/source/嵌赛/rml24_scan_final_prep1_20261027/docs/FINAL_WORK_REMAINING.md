# 最终作品剩余工作优先级

## P0：下一次上板必须完成

1. 在 Stage 7 副本安装本扫频增量并板端构建。
2. 先跑 240 帧定频回归，守住现有 98.96% 基线。
3. 改 TX 中心频率跑 240 帧窄扫频，核对发现、锁定、频率误差、准确率和完整分母。
4. 实屏验证第四个 MODE 页及 FIXED/BAND SCAN/START/STOP 控制。

## P1：形成可交付整机

1. 定频与扫频均通过后，再替换 systemd 启动脚本；模板已在 `deploy/start-dualmode-receiver.template.sh`。
2. 至少完成一次冷启动和一次重启验证，证明位流、UI、NPU、双模式服务能够恢复。
3. 做 30–60 分钟连续运行，记录帧数、失败、内存、FD、温度和恢复能力。此前用户延后过这一项，它仍没有完成。
4. 固化现场演示顺序：上电 → 定频分类 → 瀑布 → 星座 → 改 TX 频点 → 扫频锁定 → 分类。

## P2：竞赛材料与工程展示

1. 输出定频/扫频准确率、混淆矩阵、首次扫描时延、锁定后时延、NPU时延、资源利用率和功耗表。
2. 说明 FPGA 的真实贡献与边界；不要把当前未进入 24 类模型核心的逻辑夸大。可展示已验证的视频/帧缓冲、数据通路或硬件特征模块，但必须与最终运行路径证据对应。
3. 完成外壳、走线、散热、适配器品字口、板端开关孔和顶部 RX 引出。
4. 制作答辩 PPT、系统框图、测试视频、故障回退卡和 3 分钟演示脚本。
