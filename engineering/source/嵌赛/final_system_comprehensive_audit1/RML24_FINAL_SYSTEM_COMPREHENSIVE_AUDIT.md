# RML24 最终系统全面审计

审计日期：2026-10-18  
目标：双 SDR 验证的 24 类 BF16 信号识别系统，并最终收敛为板端接收系统。  
原则：只读审计既有工程；不碰板、不启动 SDR、不改模型/DSP/门限、不覆盖验证树。

## 总结结论

项目已经具备可靠的 BF16 24 类模型、ZG330 NPU 映射、干净 IQ 数字直注、双 SDR 帧恢复、诊断重放和大量主机回归测试。核心研究链质量较高。

但当前还不是一个统一的“最终 24 类接收产品”。主要原因是：验证用的 24 类双 SDR runner、旧 RML23 常驻 `live-rx`、板端 framebuffer UI、独立 Qt 星座图工具、扫频实现和 FPGA 试验工程仍是多条未完全接合的工程线。

## 已验证能力

| 模块 | 当前证据 | 结论 |
|---|---|---|
| BF16 24 类模型 | 122/122 计算算子映射 ZG330；仅输入/输出在 host | 可部署到 NPU |
| 板端数字直注 | 24/24，raw24 保持 WC/SC 独立 | 板端模型与标签接线成立 |
| 23 类公共 RF 链 | BPSK+4ASK 2/2 通过 | 双 SDR、控制、同步与 NPU 公共链有基线 |
| 24 类双样本 RF | 部分轮次 2/2 通过；部分轮次被 residual 0.10 门限拒绝 | 能工作，但门禁稳定性未收口 |
| 失败样本强制分类 | 30/30 Host BF16 与 baseline 一致且标签正确 | 被拒样本仍含可识别信息；不能据此直接改门限 |
| 离线星座 UI | 桌面构建、颜色、稳定性与离线交互已验证 | 适合诊断，不是实时最终 UI |

## P0：最终系统必须完成

1. **建立唯一 RML24 运行链。** 当前一键脚本和 `live-rx` 默认仍使用 `model_rml23/model_24class_ZG`、RML23 23 类合同与合并输出；必须新增独立 RML24 launcher、模型身份、raw24 协议和 UI 解析，禁止覆盖历史 RML23 链。
2. **明确最终接收场景。** 若最终系统接收带 canonical 前导/训练的受控帧，可复用当前恢复链；若目标是任意外部未知信号的被动调制识别，则不能依赖测试发射端的已知训练帧，必须补 acquisition/channelization/window selection、CFO 范围和域泛化验证。
3. **完成 24 类真实 RF 前瞻验证。** 现有 30 个样本只覆盖 BPSK/4ASK 且是失败条件抽样。必须执行已经准备的 24 类正样本与无信号、错误同步、低相关、削顶等负例计划，才可决定是否修改 residual 门限。
4. **实现真正扫频。** 最终 `live-rx` 接受 `BAND_SCAN` 命令但没有把它接到 LO sequencer；目前按钮只改变状态。必须接入真实 `set_rx_lo`、驻留、进度、停止/恢复和结果聚合，并做板端验证。
5. **形成唯一可追溯发布包。** 冻结模型、二进制、标签、协议、UI、启动/停止脚本、参数与 SHA，历史 fix/work 树改为只读档案，避免启动错误版本。

## P1：强烈建议在最终展示前完成

1. 将星座图 `IqFrameSource` 接到非阻塞 Unix socket 或共享内存；当前只有 `FileIqFrameSource`。
2. 板端 UI 升级到 raw24，展示真实 top-k、置信度、RF 门禁原因、连接状态、扫频进度；禁止把示例诊断数字当实测值。
3. 在目标板/显示器上测端到端 FPS、CPU、RSS、NPU 延迟和长时间稳定性。WSLg llvmpipe 的性能不能代替板端证据。
4. 增加 OOD/低置信度“未知/无法判定”状态，避免未知信号被强制标成 24 类之一。
5. 补最终系统 Vivado 综合/实现、CDC/DRC、利用率、功耗和时序报告。目前 2.19% LUT 报告只是 PS/PL 控制烟测，不代表最终数据通路。

## P2：可在主链稳定后推进

1. 在保持模型输入逐字节/数值等价的前提下，将确定性的预处理、缓存、FFT/功率统计等迁到 PL；不要为了提高利用率而改变数据分布。
2. 完成外壳尺寸实测、接口开孔、散热与装配试打。当前 enclosure 是参数化粗模。
3. 更新报告证据台账；现有 report-evidence 工程仍把后来已完成的 residual audit 和 desktop UI 标为 pending。

## 外壳专项补充

- 原粗模具备上下壳、四角紧固、主板螺柱、接口孔、通风孔和三种试配片；独立STL检查确认原底壳、顶盖和试片均无零面积三角形、开边或非流形边。
- 42项尺寸台账全部仍是占位状态，不能直接视为适配实物。
- 当前220 mm壳长对220 mm打印平台没有裙边/热床余量；Pluto占位体约穿入右侧内壁0.4 mm。
- 原7 mm×约64.6 mm角柱偏细；塑料柱咬合孔与顶盖通孔共用3.2 mm也不合理。
- 已在独立`enclosure_cad_improved1_work`中加入参数断言、打印平台/碰撞告警、实际布尔重叠、10 mm角柱、双加强筋、独立2.7 mm pilot与3.4 mm顶盖通孔，以及M3三孔径试片。改进底壳/顶盖/装配体/试片均通过独立网格检查。
- 这些结构改进不解除尺寸阻塞；最终打印前仍必须实测板卡、孔位、散热器、Pluto、插头包络、SMA和线缆弯曲空间。

## UI 专项结论

- 板端 framebuffer UI 可用、工程风格统一，但固定 1280×720、英文信息密集、RML23/23 类绑定，参数页只有频谱标量而非频谱曲线。
- `BAND_SCAN` 页面存在，但最终 `live-rx` 没有执行真实扫频。
- Qt 星座图工具布局清楚、颜色语义可靠，但它是离线工具：无 SDR 控制、无实时帧源、无扫频；旧标题仍为 RML23，窄屏会挤压，QtQuick.Dialogs 1.3 有绑定告警。
- 最佳方向不是维持两个互不相干的 UI，而是保留轻量板端主界面，并把星座图组件通过独立数据通道接入；接收/NPU 线程不得被渲染阻塞。

## 模型与准确率边界

- BF16 解决了原 24 类 INT8 下 AM-SSB-SC 的量化崩塌，BF16 是当前精度/部署兼容性的合理选择。
- 干净模型兼容数据与高 SNR 数据表现强；RadioML 全 SNR 总体准确率受低 SNR 显著拖累，256QAM 与 AM-SSB-SC 是弱类。
- BPSK/4ASK 受控帧成功不能证明任意外部 RF 泛化。旧真实 QPSK 外部采集曾出现明显域偏移，因此最终报告必须区分“受控链验证”和“被动未知信号识别”。

## 安全结论

- 本审计未删除、移动、覆盖或修改任何既有验证树。
- 未启动板卡、SDR、网络服务、Vivado 或安装程序。
- UI 美化在独立 `ui_constellation_polish1_work` 中进行；不改变模型、DSP、门限、协议或板测结论。
