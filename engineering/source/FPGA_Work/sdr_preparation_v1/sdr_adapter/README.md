# sdr_adapter — non-model system layer

The SDR / pipeline / performance / logging / recovery layer for the FMQL30TAI
system. **Model work is out of scope here** (it is owned by a separate API);
this directory contains only the non-model plumbing, is **iCraft-free**, and
therefore compiles and unit-tests on the host *and* on the board.

## Modules (all header-only unless noted)

| File | Role |
|------|------|
| `iq_frame.hpp` | `iq::Frame` + `iq::Source` contract (1024 complex int16/frame). |
| `sequence_monitor.hpp` | Detects overflow / drop / duplicate / reorder / discontinuity / short-frame / inferred gap. |
| `iq_source.hpp` / `iq_source.cpp` | `FileIqSource` (frozen replay), `SyntheticIqSource` (deterministic simulated input), `SdrIqSource` (placeholder, throws). |
| `categories.hpp` | `cat::Contract`: frozen-8 / current-10 / target-12 class orders (validated `[8,16]`). |
| `preprocess.hpp` | Reference (float) deployment physical frontend: power / lag1_real / lag1_imag. |
| `classify.hpp` | `classify::Classifier` interface + `MockClassifier` (clearly-marked MOCK logits) + softmax/argmax/top1. |
| `result_frame.hpp` | `rf::ResultFrame` per-frame verdict. |
| `iio_backend.hpp` | `iio::Backend` abstraction + `RawChunk` (device read contract). |
| `mock_iio.hpp` | `iio::MockBackend` — fake IIO with fault injection (short read / timeout / overflow / discontinuity / drop / stream break / backpressure). |
| `pluto.hpp` | `pluto::Config` (URI/center/sample rate/RF BW/gain mode/gain/buffer/timeout) + `pluto::PlutoIqSource` (optional-compile libiio). |
| `unix_socket_sink.hpp` | `ui::UnixSocketSink` — HDMI/UI JSON-lines over a Unix domain socket. |
| `offline_chain.hpp` | `chain::run` — FileIqSource → preprocess → classify → ResultFrame → sink (end-to-end). |
| `offline_e2e_main.cpp` | Runnable offline end-to-end demo (emits JSONL to stdout + optional socket). |
| `perf_stats.hpp` | Per-stage latency: sdr_capture / resample_frame / plddr_transfer / fpga_process / npu_infer / end_to_end. |
| `logging.hpp` | Leveled, timestamped logger (stderr + optional file). |
| `ui_report.hpp` | JSON-lines UI interface (`result` / `status` / `metric`) + `result_frame_line` + `ui::Sink` / `StdoutSink`. |
| `config.hpp` | `cfg::Config` + flat key=value parser + default writer (incl. `pluto_*` fields). |
| `pipeline.hpp` | Three-stage state machine skeleton + error-recovery decision table. |

## Build & test (host or board)

```sh
cd tests
./run_tests.sh          # g++ -std=gnu++17, builds and runs the unit tests
```

The tests cover `FileIqSource`, `SyntheticIqSource`, `SequenceMonitor`,
`PerfStats`, `cfg::Config`, `ui::` serialization, the recovery policy, plus the
new `categories` / `preprocess` / `classify` / `result_frame` / `mock_iio` /
`pluto` / `offline_chain` / `unix_socket` modules.  No iCraft SDK, no SDR, no
board is required.

### Offline end-to-end demo

```sh
cd sdr_adapter
g++ -std=gnu++17 -Wall -Wextra -O2 -I. offline_e2e_main.cpp iq_source.cpp -o offline_e2e
./offline_e2e --frames 8                       # synthetic IQ -> FileIqSource -> JSONL
./offline_e2e --iq frozen_iq.bin --frames 100  # replay a real frozen IQ buffer
./offline_e2e --frames 8 --socket /tmp/ui.sock # also fan out to a Unix socket
```

Every emitted record carries `"mock":true` — the classifier is MOCK and must never
be reported as real inference.

## Config

`../config/sdr_adapter_config.conf` is the default config; it is generated by
`cfg::write_default_config()` (identical text).  SDR fields are `0` / empty =
"unspecified until the device arrives".  The `pluto_*` fields carry the
ADALM-Pluto runtime parameters (URI / center freq / sample rate / RF bandwidth /
gain mode / gain / buffer length / timeout) — `0` / empty = unspecified, never
fabricated device measurements.

## Relationship to board_package

`../board_package/continuous_joint_stress.cpp` is the board program that
actually drives the FPGA + NPU on one persistent Device.  This directory is the
**host-testable design + policy + contract layer** that the board program (and
the future SDR adapter) will consume.  The two are intentionally separate so
the system layer can be verified offline and without the NPU SDK.
