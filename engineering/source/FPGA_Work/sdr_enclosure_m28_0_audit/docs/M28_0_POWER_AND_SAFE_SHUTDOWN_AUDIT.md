## 2. 电源分配方案（概念，非冻结）

| 方案 | 说明 | 评估 |
|---|---|---|
| Q1 单 12V 适配器 → 板卡，屏幕/风扇从板卡取电（若板有对外 5V） | 最简 | 需确认板卡 USB Host 每口 +5V 是否满足屏幕/风扇功率 |
| Q2 单 12V 适配器 → 板卡 + 独立 DC/DC 供屏幕/风扇 | 稳 | 需确认屏幕/风扇总功率后定 DC/DC 参数 |
| Q3 独立多路适配器 | 复杂 | 不推荐，违背便携 |

**结论：Q1 优先尝试，Q2 备选；在屏幕/风扇功耗实测前，不锁定 DC/DC 型号与适配器功率。**

## 3. 功耗估算（CONCEPT ONLY，非加工依据）

- 板卡：12V 输入，6A eFuse 上限（**上限≠实际功耗**），实际功耗**未测**。
- Pluto：USB 5V 供电，约 <3W（典型，需官方页复核）。
- 屏幕：7 寸 HDMI 屏典型 3~6W，**待测**。
- 风扇：0.5~2W 量级，**待测**。

> 上述均为方向性量级，**不得**据此定适配器额定功率/DC-DC 输出。用户有功率计则实测板卡+屏+风扇总功耗。

## 4. POWER 按钮与安全关机（关键）

### 4.1 问题

- Linux 直接断电会导致 SD 卡文件系统损坏。
- 任务书基线只有"POWER 按钮"，未定义关机语义。

### 4.2 方案（概念，需用户确认后实现）

| 方案 | 说明 | 评估 |
|---|---|---|
| K1 **瞬时按钮 → GPIO → Linux 安全关机** | 短按触发 `shutdown`，长按（≥4s）强制断电 | 首选：按钮接板卡可编程 GPIO/按键，由软件处理 |
| K2 硬件电源开关直切 | 硬切断 12V | 风险：SD 卡损坏，仅作最终手段 |
| K3 软硬结合 | K1 软件关机 + 关机完成后软件/硬件断电 | 最佳，需额外电源控制电路 |

**结论：采用 K1（按钮→GPIO→安全关机）为基线；长按强制断电作为兜底。** 按钮型号/孔径待测（D-4），GPIO 接线待板卡按键资源确认。

### 4.3 指示灯语义

- POWER 指示灯：待机/上电亮。
- SYSTEM 指示灯：建议由软件驱动（启动完成/运行/关机中），体现"软关机完成"状态。

## 5. 风险

| # | 风险 | 处置 |
|---|---|---|
| P1 | 未安全关机直接断电 → SD 损坏 | 按钮走 GPIO 软关机（K1），长按才硬断电 |
| P2 | 屏幕/风扇 5V 电流不足 | 实测功耗后决定是否加 DC/DC（Q2） |
| P3 | 适配器功率/极性错误 | 12V 中心正极待适配器型号确认；不冻结参数 |
