## 1. FPGA+NPU+CPU 组合合理性判断（任务书 §八）

**待判组合**：FPGA 做 FFT/能量检测/频段候选提取/DMA 环形缓冲/显示搬运；NPU 做 24 类调制识别 + 可选信号存在检测/多任务；CPU 做 UNKNOWN 拒识/多帧融合/扫频控制/事件记录/触摸 UI。

### 判定：**合理，且优于「继续扩大单个分类模型」，有一处修正。**

**合理的部分（与异构 SoC 设计意图一致）**：
- **FPGA 分配正确**：FFT/能量检测/频段提取/DMA/显示搬运恰是「高速、固定流程、强并行」任务，且当前 **DSP 94% 空闲**（`Vivado报告`）可直接承接，无需挤占 CPU/NPU。
- **NPU 分配正确**：24 类卷积推理是 NPU 的主场；24 类 vs 12 类仅末层差异（MAC +0.0033%，`推导`），算力余量充足。
- **CPU 分配正确**：UNKNOWN 拒识（logit_margin O(12)）、多帧融合、扫频状态机、事件记录、触摸 UI 均属「控制/轻量评分/状态机」，落 CPU 恰当；4 核中 ~3 核空闲（`推导`）。

**必须修正的一点**：
- **「可选信号存在检测放 NPU」应改为优先 FPGA**。能量检测/谱峰检测是确定性 DSP（`dsp_measure.hpp`/`signal_presence.hpp` 已有实现），把它改造成神经网络**违反「不为了使用 NPU 而把简单阈值判断改造成神经网络」的红线**。信号存在检测应落 FPGA 能量/谱峰，NPU 保持专注调制识别（除非确有必要做轻量网络化，需另立依据）。

**与「继续扩大单个分类模型」对比**：
- 单模型路线让 FPGA DSP（94% 空）、NPU（推导 ~99% 空）、CPU（3 核）、DDR 带宽全部闲置，无法体现 FMQL30TAI「PS+NPU+PL 单芯片异构融合」的核心卖点。
- 本组合把三类算力各自擅长的事并行起来，每项功能都对应真实应用价值（监测/识别/告警），**作品竞争力显著更强**。
- 前提约束：E（多信号）/J（多任务）受「周期性尖峰未解 + 多模型驻留 UNKNOWN」约束，属远期；**不做为跑满资源而无意义堆功能**。

## 2. 最终 12 问回答（任务书 §九）

**Q1 当前板卡是否明显性能过剩？**
是。NPU 推导利用率 ~1%（`推导`）、FPGA DSP 6.0%（`Vivado报告`）、LUT/FF ~50%、CPU ~3 核空闲、DDR 带宽富余。但「过剩」是单任务视角；异构 SoC 的设计目标就是并行多任务，跑不满是正常——价值在于**用余量承载更多并行功能**，而非填满。

**Q2 当前真正的瓶颈在哪里？**
不在计算（NPU ~1ms/帧）。真正的瓶颈是：① **Device 生命周期管理**（每帧 reopen ≈263ms vs 持久 reset(1) ~0.67ms，`实测`，已修复待上板复测）；② **周期性 425–937ms 尖峰**（每 6 cycle 一次，根因未确认，`实测`用户日志转录）；③ 每帧 **重复内存分配**（producer/NPU 输入输出均 fresh 分配，`代码常数`）；④ **24 类模型未训练**（能力天花板，`无证据`）。

**Q3 FPGA/NPU/CPU/DDR 分别还剩多少余量？**
FPGA：DSP **94% 空**（376 个）、BRAM ~48%、LUT ~47%、FF ~55%，但 Slice 打包 98.19% 需注意布线（`Vivado报告`）。NPU：推导 **~99% 空**（`推导`）。CPU：~3 核空闲（`推导`）。DDR：带宽富余（framebuffer 110MB/s vs PL DDR ~6.4GB/s，`推导`）。

**Q4 最值得增加的三个功能？**
**A（24 类识别）**、**F（实时频谱/瀑布图）**、**D（信号存在检测）**。其中 D 与 H（参数估计）代码已存在，属「白捡」。

**Q5 哪个最能提高比赛竞争力？**
**A（24 类实时识别）**——直接对标任务升级、结构零风险、评委认知清晰；F（瀑布图）为视觉补充。

**Q6 哪个最能提高真实应用价值？**
**C（OOD-U/UNKNOWN 拒识）**——真实环境最需要「拒绝未知类」；与 D（信号存在检测）组合解决「不误报空信号」+「不误认未知信号」两大真实痛点。

**Q7 24 类模型是否应成为正式主模型？**
**应（作为下一阶段主功能），但当前不能直接替换**。24 类与 12 类同骨干（`代码常数`），结构/算子零风险；但 24 类**未训练**（`无证据`），须先 GPU 训练收敛→int8 精度过门→ONNX 导出→Gate7 门禁通过，才可切主模型。

**Q8 是否值得保留 12 类快速模型作为第一级？**
**值得，但定位应是「已验证主力 + 降级路径」，而非运行时两级级联**。12 类已部署且 Gate7 过门（`契约文档`），24 类未训练有风险；保留 12 类可在 24 类不达标时快速回退。真正的「两级分类」（先大类后细类）属 P3 远期，无既有实现与收益证据。

**Q9 OOD-U 应继续做后处理，还是必须进入训练阶段？**
**两者都要，分阶段**。后处理（M20 已交付）是零训练成本基线，立即可用；但 near/far 6.03%/10.33% 是冻结模型能力天花板（`结果JSON`），**只有进入 OE/Energy 训练阶段才能根本改善**。**不得把单纯调阈值描述为根本改善**。

**Q10 怎样扩展才能体现板卡能力，而不是无意义跑满资源？**
让三类算力并行做**各自擅长且有真实价值**的事：FPGA 做 FFT/能量检测/频谱/显示（用 DSP），NPU 做 24 类识别（用卷积），CPU 做控制/拒识/记录/UI。每项功能都绑定一个真实应用价值（监测/识别/告警/记录），而非为占资源而占。红线：**不为用 NPU 而把阈值判断改神经网络，不为跑满而堆无意义功能**。

**Q11 哪些功能会增加风险，比赛前不建议做？**
**E（多信号检测）、J（多任务网络）、K（射频指纹）、B（两级分类）**。E/J/K 实现难度/板端验证/NPU 兼容/数据需求均为最高档（见评分矩阵）；B 无既有实现与收益证据。且 E/J 受「尖峰未解 + 多模型驻留 UNKNOWN」双重约束。

**Q12 推荐的最终系统框图和阶段路线？**
见 §3 框图与 §4 阶段路线。核心：**FPGA=信号域处理（FFT/能量/频谱/显示），NPU=调制识别（24 类/OE），CPU=语义层（拒识/融合/控制/记录/UI），DDR=帧缓存+IQ 环形缓冲+事件回放**，按 A→B→C 三阶段递进，风险逐级递增、能力逐级增强。

## 3. 推荐最终系统框图

```
                    ┌─────────────────────────────────────────────────────┐
                    │                 Pluto SDR (AD9364, 外接)             │
                    │         2.56M×20 / 3.84M×30 → 128kHz IQ              │
                    └───────────────────────┬─────────────────────────────┘
                                            │ USB / libiio (int16 I/Q 交织)
                                            ▼
   ┌──────────────────────────────────────────────────────────────────────────┐
   │  FPGA (PL)  — 高速/固定流程/强并行（DSP 94% 空闲可承接）                   │
   │   • FIR 重采样 + NCO + receiver_scale 预处理                              │
   │   • 能量检测 / 谱峰检测（D：NO_SIGNAL vs SIGNAL_PRESENT）                 │
   │   • radix-2 FFT（H：SNR/带宽/谱质心/CFO；F：频谱/瀑布图/峰值保持）         │
   │   • DMA + IQ 环形缓冲（L）+ framebuffer 显示搬运                           │
   └───────┬───────────────────────────┬─────────────────────────────────────┘
           │ [1,2,1024] fp32           │ 帧缓冲(720P) / 频谱 / 参数
           ▼                           ▼
   ┌──────────────────────┐   ┌──────────────────────────────────────────────┐
   │  NPU (ZG330, 8TOPS)  │   │  CPU (4×A53)  — 控制/语义/记录/UI               │
   │  • 24 类调制识别     │   │  • UNKNOWN 拒识（logit_margin 后处理）          │
   │  • OE/Energy 模型    │   │  • 多帧融合/时序稳定（I）                        │
   │   (远期: 多任务头)   │   │  • 扫频控制/自动驻留（G）                        │
   └──────────┬───────────┘   │  • 事件记录（L）+ 触摸 UI                       │
              │ 12/24 logits  └────────────────────────────────────────────────┘
              ▼
        argmax → 已知类 / UNKNOWN → UI 显示
```

数据流契约：IQ → FPGA 预处理 → `[1,2,1024]` fp32 → NPU → raw logits → CPU 评分/判决 → UI；**OOD 判决在 CPU（后处理），根本改善靠 NPU 上 OE 训练模型**；DDR 承载帧缓存 + IQ 环形缓冲 + 事件回放。

## 4. 阶段路线

| 阶段 | 内容 | 对应路线 | 前置门禁 | 风险 |
|---|---|---|---|---|
| 阶段 0（当前） | 复测尖峰根因（latency 回传）+ 12 类 Gate7 infer_us 回填 | — | 尖峰根因确认 | 低 |
| 阶段 1 | A(24 类训练+导出+int8 校验) + C(OOD 后处理接线) + D + H + I | 路线 A | 24 类训练收敛 / int8 过门 / Gate7 门禁 | 低 |
| 阶段 2 | + F(瀑布图) + G(自动巡检) + L(记录回放) | 路线 B | 阶段 1 稳定 / 显示带宽实测 | 中 |
| 阶段 3 | + E(多信号) + J(多任务) + K(指纹) | 路线 C | 尖峰已解 / 多模型驻留支持确认 | 高 |

**红线与最终状态**：本文档只做调研，最高状态 **`M21-0-RESEARCH-COMPLETE`**；严禁 `HARDWARE_PASS` / `PERFORMANCE_PASS` / `PROJECT_COMPLETE`。所有利用率/性能数字必须带来源，缺证据即 `UNKNOWN`。
