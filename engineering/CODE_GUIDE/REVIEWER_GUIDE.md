# 评审阅读指南

本作品将真实SDR输入经CPU同步恢复和two-DC处理后送入NPU识别24类调制；FPGA承担显示频谱侧路，包含Hann窗、1024点FFT、模平方及缓冲。CPU同时管理定频、搜索锁定、连续巡扫、增益与界面事件。PC是独立发射控制端，不能把发射标签当作接收推理输入。

## 建议阅读顺序

1. 先看正式快照 `FINAL_BOARD_SNAPSHOT_20261102/README.md`，了解板端版本与外部依赖。
2. 在[模块与关键入口](MODULE_ENTRY_POINTS.md)依次看服务启动、进程监管、接收恢复、模式、UI、模型与FPGA。
3. 找某个文件时打开[可搜索逐文件索引](FILE_BROWSER.html)，输入文件名、模块名或符号。索引列出每个原清单文件的所属模块、文件种类、版本状态和用途依据；它不是每个函数的算法说明。
4. 查原目录路径时使用 `ORIGINAL_PATH_INDEX.csv` 或根目录 `SOURCE_MAP.json`。去重后多个原文件可能共用一个存放文件；原始最新工程路径可能映射到较早目录中的同字节副本，这不是漏包。
5. 需要恢复全部原目录时按 `README_源码说明.md` 使用 `restore_tree.py`，输出到不存在的新目录。恢复后可能产生大量重复内容。

## 文件归属与版本

- `FINAL_BOARD_SNAPSHOT_20261102` 是正式板端只读快照，但其中也保留兼容或旧测试源码；不代表所有文件同时在运行。以service→launcher→监管器→子进程及版本回执判断实际链路。
- `TRAINING_REFERENCE` 是最终模型与检查点的核验入口；基础YAML不等于所有所选试验参数。训练数据集、SDK和工具安装包仍是外部依赖。
- `MULTIFREQUENCY_TX_CANDIDATE_20261102` 是PC单信号/多频点工程，状态看其交接；`ADDITIONAL_CANDIDATES`与其他历史目录不能自动当作正式版本。
- `source` 保存开发和验证历史。被否决、试验性实现与最终复用文件都可能在其中，按状态与证据阅读。
- `vendor`命名不必然意味着第三方代码；索引中“供应商/生成”也只是已知路径或文件类型标记，最终版权归属以原许可与头部为准。供应商视频、DDR、NPU和FFT IP不应全部计为自研内容。

## 如何使用逐文件说明

人工核对的关键入口提供明确用途；其余文件提供可验证的类别、目录归属、源文件自述及静态符号。源文件自述保留原文，可能包含过期candidate或状态描述，不能独立证明当前状态。无法可靠判断的辅助文件标为历史/需结合工程阅读，不编造具体算法行为。

`FILE_INDEX.csv`可在Excel搜索和筛选；`ORIGINAL_PATH_INDEX.csv`覆盖去重前所有原始路径。HTML索引离线可用，无网络请求。索引不包含商业工具、数据集或完整设备镜像。
